1. What EdVidura is (one minute)

EdVidura is a learning tool that opens inside the customer’s LMS (Moodle) via LTI 1.3. We do not rebuild Moodle. Moodle keeps courses and the official gradebook; EdVidura adds quizzes and later modules (content, skills, AI) with strict multi-tenant data separation.

Two delivery forms later: shared cloud SaaS, and private offline instances for regulated / defence customers.

4. Proposed development plan (next 90 days)

Week 1–2 — Stabilize Slice A

  • Confirm AGS end-to-end in every demo Moodle (checklist for juniors)
  • Minimal onboarding UI (create tenant/platform without raw SQL)
  • Merge remaining docs/contracts; leadership initials on DEC board
  • Demo script: student launch → quiz → gradebook → teacher attempts

Week 3–6 — Slice A hardening + foundations

  • Request-scoped tenant context (ContextVar) + audit of tenant-tagged writes
  • Event envelope v1 on quiz submit (outbox table, still Postgres)
  • Isolation tests for quiz_attempts in CI
  • Basic ops: health, structured logs, backup note for shared DB

Week 7–12 — Slice B start (content) if capacity allows

  • One technical manual / eBook path with version tracking (no AI yet)
  • Same dual rule: cloud path first; offline/enclave design notes only
  • Freeze skills registry schema on paper before coding skill features
Exit goal for 90 days Reliable demo for a real pilot conversation: onboard a Moodle → launch → assess → grade back → teacher view → proof that Tenant A cannot see Tenant B.

5. What we are explicitly not building in this window

  • AI chatbot / auto-grading / GPU appliances
  • XR / immersive labs
  • Cross-command federation
  • Keycloak as primary IdP (Moodle LTI remains front door)
  • Canvas / Open edX
  • Schema-per-tenant or DB-per-tenant for SaaS
